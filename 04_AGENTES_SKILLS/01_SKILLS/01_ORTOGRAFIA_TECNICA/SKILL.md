# Ortografía técnica del proyecto

1. Identifica si el texto es documentación, tesis, comentario o narrativa de resultados y conserva su nivel de formalidad.
2. Corrige tildes, concordancia, puntuación, repeticiones y frases ambiguas. Usa español técnico claro, sin adornos ni afirmaciones nuevas.
3. Preserva nombres oficiales de variables, tablas, rutas, paquetes y archivos fuente. No «corrijas» identificadores mediante sustituciones globales.
4. Mantén cifras, unidades, denominadores, intervalos, signos, referencias y significado estadístico. Si una frase contradice una tabla, señala la discrepancia; no inventes la cifra correcta.
5. Usa de forma consistente ENDI, INEC, ESPOL, PostgreSQL y Python. Conserva citas literales y títulos oficiales; diferencia las correcciones editoriales de dudas metodológicas.
6. En archivos Markdown, preserva enlaces, bloques de código y tablas. Revisa que el texto corregido siga siendo válido y que las rutas existan cuando sean internas.
7. Si el usuario solo solicita corrección lingüística, no alteres código, métodos ni estructura de datos. Resume únicamente cambios sustantivos o dudas pendientes.
