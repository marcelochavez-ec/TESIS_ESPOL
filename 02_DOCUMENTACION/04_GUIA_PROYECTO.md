# GUÍA DEL PROYECTO TESIS ESPOL

1. **Objetivo.** Conservar fuentes ENDI, mapear sus variables y recargar de forma reproducible las seis tablas fuente de research_lab.endi. La recarga crea y valida sus PK, FK y restricciones según la guía ENDI R2; el diagrama está en 07_MODULOS/07_MODELO_ENTIDAD_RELACION.md.
2. **01_DATOS_FUENTE.** Seis RDS numerados 01–06 y un diccionario consolidado XLSX 07 con seis hojas. El manifiesto versión 2 registra esta nueva entrega del Excel; los RDS mantienen sus bytes; los nombres originales y SHA-256 están en `05_CONFIGURACIONES/01_PROYECTO.json`. Esta carpeta no se publica en GitHub ni se copia a la imagen Docker.
3. **02_DOCUMENTACION.** Los PDF originales están numerados 01–03 y en mayúsculas. Esta guía es 04, la receta GitHub es 05, el inventario es 06 y las carpetas 07–09 contienen módulos, mapeo y validaciones.
4. **03_PROCESOS_ETL.** `01_ETL_FUENTES.py` genera el catálogo; `02_MAPEO_POSTGRESQL.py` resuelve tipos y lectura tabular; `03_VERIFICAR_ENTORNO.py` comprueba versiones y operaciones sintéticas; `04_GESTION_PROYECTO.py` controla integridad, pruebas y reproducción; `05_MODELO_RELACIONAL.py` aplica y verifica claves y relaciones; `07_DICCIONARIO_VARIABLES.py` sincroniza etiquetas y restricciones. `03_PROCESOS_ETL/05_PRUEBAS/01_PRUEBAS_MAPEO.py` contiene la suite.
5. **04_AGENTES_SKILLS.** Un solo `AGENTS.md` vigente y cuatro skills en `01_SKILLS/`. Se eliminaron el agente archivado, la guía duplicada y el iniciador PowerShell. Para trabajar en Codex se abre la carpeta 04 y se lee ese agente; no existe un agente de proyecto en la raíz.
6. **05_CONFIGURACIONES.** Un manifiesto `01_PROYECTO.json`, un `environment.yml`, un solo `requirements.txt`, Dockerfile, compose.yaml y archivos técnicos de exclusión. Las excepciones de nombres son formatos reconocidos por las herramientas y permanecen encarpetadas.
7. **Punto único de configuración.** El manifiesto indica archivos, hashes originales, tablas lógicas, rutas, margen VARCHAR, aliases documentales y valores predeterminados de PostgreSQL. Los aliases corrigen cinco diferencias entre nombres del diccionario de desarrollo infantil y la base, sin renombrar las variables originales.
8. **Mapeo.** El catálogo `08_MAPEO_ENDI/01_MAPEO_VARIABLES.csv` describe cada variable: fuente, tabla, tipo recuperado, clase de valores, tipo SQL propuesto, nulos, longitudes y etiqueta con nombre del diccionario. `02_RESUMEN_MAPEO.json` agrega conteos; `03_TIPOS_POSTGRESQL.sql` es únicamente una propuesta de CREATE TABLE, no ejecutada.
9. **Ejecución local.** Desde la raíz se utiliza `conda run -n espol python -B 03_PROCESOS_ETL/04_GESTION_PROYECTO.py reproducir`. La acción comprueba versiones exactas, hashes, pruebas y dos resultados idénticos; no conecta a PostgreSQL ni crea tablas.
10. **Contenedor.** `docker compose -f 05_CONFIGURACIONES/compose.yaml build` construye la imagen. `docker compose -f 05_CONFIGURACIONES/compose.yaml run --rm mapeo` ejecuta la misma reproducción. Los datos se montan en solo lectura y la documentación conserva las salidas. Detalles en `07_MODULOS/05_REPRODUCIBILIDAD.md`.
11. **Conexión externa.** El código recibe PGHOST, PGPORT, PGDATABASE, PGUSER y PGPASSWORD o pgpass. No hay contraseñas en los archivos. La verificación SQL opcional del script 03 hace solamente SELECT en una transacción de lectura.
12. **Inventario.** `06_INVENTARIO_PROYECTO.csv` es el único inventario global: ruta relativa, clase, tamaño, hash y nombre original cuando aplica. Se regenera con `python -B 03_PROCESOS_ETL/04_GESTION_PROYECTO.py inventariar`; su propia fila no lleva hash por autorreferencia.
13. **GitHub.** El remoto es [marcelochavez-ec/TESIS_ESPOL](https://github.com/marcelochavez-ec/TESIS_ESPOL). Se sigue `05_RESPALDO_GITHUB.md`, que conserva la historia existente y configura las exclusiones de fuentes, pruebas y rastros locales. La receta explica clonación, exclusiones, ejecución y sincronización.
14. **Orden de etapas.** Mapeo completo → COPY de las seis fuentes con sus tipos → creación y validación del modelo relacional → sincronización del diccionario y comentarios → commit conjunto. La guía se leyó completa y sus excepciones se contrastaron con los datos; no se eliminan registros para imponer relaciones.

15. **Ejecución completa autorizada.** El autor inicia Docker en modo Linux, abre una terminal en la raíz y ejecuta el siguiente comando. Comprueba fuentes, entorno y mapeo antes de sobrescribir únicamente las seis tablas declaradas. Solicita la clave de PostgreSQL si no existe PGPASSWORD. El detalle, alcance y recuperación ante errores están en `07_MODULOS/06_RECARGA_POSTGRESQL.md`.

```powershell
docker compose -f 05_CONFIGURACIONES/compose.yaml run --build --rm recarga
```

16. **Resultado.** Se conservan los informes `09_VALIDACIONES/12_RECARGA_POSTGRESQL.json` y `15_REPETICION_RECARGA.json`. El servicio mapeo y la acción reproducir siguen disponibles para verificar sin escribir en PostgreSQL. La recarga requiere un servidor accesible, la base research_lab, el esquema endi existente, permisos de sustitución y las entradas originales.

17. **Contenido local excluido de GitHub.** 01_DATOS_FUENTE, 03_PROCESOS_ETL/05_PRUEBAS, 02_DOCUMENTACION/09_VALIDACIONES y residuos técnicos quedan fuera del respaldo. Se incluyen scripts, agentes, configuración, catálogo, SQL y documentos PDF/Word/libros. La suite local es opcional para reproducir una copia publicada; su ausencia se informa sin simular pruebas correctas. Git ya está inicializado localmente y core.excludesFile apunta al archivo de la carpeta 05; el respaldo conserva el historial remoto de main.

18. **Modelo físico.** Hay 6 PK, 12 FK, 7 UNIQUE y 11 CHECK, además de NOT NULL e índices auxiliares. Se mantienen las 1.423 variables fuente y se añade una columna derivada en Salud: id_per_miembro, para enlazar miembros con Personas y conservar los 171 no miembros terminados en 77. El SQL reproducible está en 08_MAPEO_ENDI/04_RESTRICCIONES_POSTGRESQL.sql.

19. **Portada pública.** [README.md](../README.md) presenta a Marcelo Chávez, CEO de ConneXData, con su [perfil LinkedIn](https://www.linkedin.com/in/marcelochavezec/), contexto de la tesis y catálogo de carpetas y archivos. El mantenimiento se documenta en 07_MODULOS/08_PORTADA_Y_CATALOGO.md.

20. **Identidad visual.** 06_IMG/ConneXData.jpeg contiene la imagen proporcionada por el autor y se publica para utilizarla en la portada. No se utiliza el logo de ESPOL. La estructura tiene seis carpetas numeradas; README es la única excepción de presentación en la raíz.

21. **Diagrama compacto.** 03_PROCESOS_ETL/06_CONFIGURAR_DBEAVER.py guarda o verifica erd.attr.visibility=KEYS en el workspace local de DBeaver. Muestra las claves para revisar relaciones, sin alterar las variables de PostgreSQL. Se documentan reinicio, menú Any keys y configuración reproducible en 07_MODULOS/09_DBEAVER_COMPACTO.md.

22. **Diccionario consultable.** El Excel 07 consolidado alimenta endi.diccionario_variables (1.424 entradas) y su tabla auxiliar endi.diccionario_restricciones (96 vínculos de las 66 restricciones de las fuentes). La vista endi.v_diccionario_variables simplifica la consulta de etiquetas y claves; las columnas reciben sus comentarios nativos. La recarga completa lo sincroniza antes de confirmar. Se documenta en 07_MODULOS/10_DICCIONARIO_VARIABLES.md.

23. **Reporte provincial de comprobación.** `08_MAPEO_ENDI/07_REPORTE_PROVINCIAL.sql` se ejecuta como script en DBeaver sobre research_lab y no escribe objetos ni datos. Produce diez resultados: auditorías de relaciones/diccionario y tabulado de DCI con fexp de Personas para las 23 provincias continentales y el total. Se conservan n, casos y porcentaje ponderado; no calcula IC/CV ni totales poblacionales. La lectura metodológica, denominadores y resultados comprobados están en `07_MODULOS/11_REPORTE_PROVINCIAL.md`.
